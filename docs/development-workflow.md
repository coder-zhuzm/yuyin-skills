# 开发工作流

`yuyin-dev` 是通用任务入口。专业能力由当前任务适用且已安装的技能提供，安装与更新见[安装指南](installation.md)。

## 项目事实优先

先读目标项目的规则、源码、依赖、配置和测试。保留已有变更，沿用当前技术栈与设计系统。项目有确认门禁时先完成门禁；“只分析”不进入实施。

具体业务、品牌、第三方约束和已验证 workaround 属于目标项目，不随通用技能分发。优先使用已有记录，未经请求不创建 `.ai-dev` 或额外项目文档。

## 调用示例

Codex 使用 `$yuyin-dev`，Claude Code 使用 `/yuyin-dev`。

| 请求 | 预期行为 |
| --- | --- |
| 给 React 列表增加筛选，沿用现有组件库 | 读取状态和请求实现，选择适用 React 规则；验证成功、空结果与失败状态 |
| 排查 Spring 接口重复提交 | 复现、定位事务与幂等边界，保留 MyBatis/JPA 现状；补回归证据 |
| 分析 Node 服务超时，先不修改 | 只读确认调用链、超时与错误传播；给依据和最小验证方案 |
| 评估当前页面性能 | 先测量，再判断瓶颈；普通 React 不套 Next.js 专属 API |
| 审查当前 diff | 给具体位置、触发条件与影响；不为凑问题改代码 |
| 整理交接 | 在对话或用户指定载体保存事实、验证与下一步 |

## 选择专业技能

| 能力 | 使用边界 |
| --- | --- |
| React 性能、请求与组件组合 | 核实 React/Next.js 及版本；React 19 专属规则不用于 React 18 |
| UI 设计与可访问性 | 新设计或明确调整才使用设计流程；小修复不重做全站视觉 |
| Java/Spring | 核实 Java/Spring、构建与数据访问版本；JPA、目录建议不是迁移指令 |
| Node 后端 | 按实际框架、模块格式及复杂度使用示例，不自动引入分层或微服务 |
| 浏览器测试 | 优先已有工具；Python Playwright 技能不会自动补齐运行依赖 |

技能缺失时说明能力缺口，完成现有工具能验证的部分。不自动安装或升级；同名来源不清时先核实路径。上游原文不会代替用户需求、项目约束或版本兼容性判断。

## 验收与反馈

实施前明确可观察结果，实施后检查实际行为、相关回归与 diff。性能结论有前后基线；UI 有实际页面或截图；仅编译成功不能证明业务成功。报告只列实际执行的验证及未覆盖范围。

已发布的内容快照保证文件可追溯，不保证所有模型、项目和工具环境都产生相同行为。试用重点记录误触发、强制改栈、越界修改、返工和验证质量；重复缺陷优先落实到项目测试或检查工具。

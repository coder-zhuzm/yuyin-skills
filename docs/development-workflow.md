# 开发工作流

`yuyin-dev` 为 Claude Code 与 Codex 提供按任务意图组织的开发流程。安装与版本管理见[安装指南](installation.md)。

## 工作原则

| 原则 | 行为要求 |
| --- | --- |
| 基于源码 | 从实际入口、依赖、配置和执行结果确认项目事实 |
| 明确意图 | 区分只读评估、逻辑解释与代码实施 |
| 控制范围 | 沿用现有技术栈，修改与当前目标直接相关的内容 |
| 持续推进 | 自行查明可检索事实，仅询问影响正确性且无法推断的决策 |
| 保留证据 | 已验证的行为和临时解决方案作为后续排查基线 |
| 按风险验证 | 根据权限、数据、并发和业务影响选择检查范围 |
| 支持交接 | 为复杂或跨会话任务保留状态、决策与验证记录 |

项目特有的业务约束、素材要求和部署条件应写入目标项目的上下文，不纳入通用技能规则。

## 任务类型与调用示例

Claude Code 使用 `/yuyin-dev`；Codex 使用 `$yuyin-dev`。以下示例采用 Claude Code 调用格式。

| 任务 | 示例 | 预期结果 |
| --- | --- | --- |
| 功能开发 | `/yuyin-dev 功能 为知识库查询增加来源展示，沿用现有接口与页面。` | 明确验收条件，实现并验证完整流程 |
| Bug 修复 | `/yuyin-dev 修复 消息回调重复入库，保留正常处理行为并补充回归验证。` | 复现、定位、修复及失败路径检查 |
| 可行性评估 | `/yuyin-dev 评估 分析消息处理中接入人工处理的可行性，先不修改代码。` | 接入点、约束、最小方案与实施成本 |
| 逻辑梳理 | `/yuyin-dev 逻辑 从 Controller 到 Service/Mapper 梳理消息处理链。` | 调用链、分支、状态变化与代码位置 |
| 优化评估 | `/yuyin-dev 优化 评估 RAG 查询延迟，只做分析，先确定测量基线。` | 瓶颈证据、方案、代价与验证方式 |
| 优化实施 | `/yuyin-dev 优化 实施已确定的缓存方案，保持租户隔离并对比前后基线。` | 实现结果、语义检查与测量对比 |
| 代码审查 | `/yuyin-dev 审查 检查当前 diff，优先关注行为、权限和数据问题。` | 问题位置、触发条件、后果与建议 |
| 任务交接 | `/yuyin-dev 交接 整理任务状态、代码变更、验证结果与剩余工作。` | 可供后续继续执行的任务记录 |
| 开发复盘 | `/yuyin-dev 复盘 分析重复出现的问题，提出最多三项可落实的改进。` | 测试、检查工具或项目配置的改进建议 |

任务请求需说明目标与必要约束。技能是否被识别，应通过新会话中的显式调用及实际任务行为确认。

## 实施流程

1. **读取项目上下文。** 检查项目规则与 Git 状态，定位入口、依赖版本、类型协议和参照实现，保留已有未提交改动。
2. **明确需求边界。** 从源码确认可查事实；对无法推断的权限、重试或行为决策集中提问。
3. **制定验收条件。** 通常覆盖成功场景、关键失败场景和既有行为。例如重复回调只产生一次业务副作用。
4. **完成业务闭环。** 优先实现从入口到结果的可验收路径，再扩展必要的分支与异常处理。
5. **执行相关验证。** 文案调整按实际内容检查；权限、租户隔离、重试、幂等和协议转换需要覆盖关键失败与回归场景。
6. **审查并交付。** 报告行为变化、关键原因、实际检查结果和剩余限制，明确提交、推送与部署状态。

小任务使用简要验收记录；复杂或跨会话任务可使用 `templates/task.md`。生产部署、数据迁移和外部发布遵循项目规则及用户授权。

## 领域检查

| 场景 | 主要检查项 |
| --- | --- |
| 企业微信、原生微信与 RPA | 能力边界、消息来源、权限、幂等、顺序、重试与人工处理 |
| Java 后端 | Controller-Service-Mapper 调用链、事务、DTO/VO、分页、租户隔离与软删除 |
| LLM 网关 | 模型路由、协议映射、流式事件、错误透传与重试策略 |
| RAG 知识库 | 检索、重排、生成耗时，权限过滤、索引更新、引用与无答案处理 |
| Web 与 Three.js 交互 | 点击行为、状态变化、视口适配、素材加载与降级 |
| Docker 与内网部署 | 容器、端口、卷、环境变量、架构、镜像版本与业务接口 |

字段、阈值和架构以目标项目为准。性能目标根据业务基线制定，临时素材与最终交付分别验收。

## 来源与适配

工作流参考上下文工程、源码驱动开发、需求澄清、领域建模、风险验证和复盘方法。项目级适配包括按需读取参考资料、保留充分排查范围，以及按业务基线制定性能目标。

具体来源及第三方工具边界见[来源与适配说明](../SOURCES.md)。技能指令提供行为指导，执行权限与测试要求仍由目标项目管理。

## 试用与改进

试用建议覆盖一个 Bug 修复、一个功能开发和一次只读评估。记录误改、返工、重复解释、验证证据完整性及交接可用性。

重复出现的问题优先沉淀为项目检查：启动命令写入项目上下文，回归问题补充测试，格式问题交由 formatter 或 lint，术语歧义补充词汇表。每轮复盘保留最多三项可执行改进，并根据实际效果调整流程。

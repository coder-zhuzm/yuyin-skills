# 开发工作流

`yuyin-dev` 是通用任务入口。专业能力由当前任务适用且已安装的技能提供，安装与更新见[安装指南](installation.md)。

## 项目事实优先

先读目标项目的规则、源码、依赖、配置和测试。保留已有变更，沿用当前技术栈与设计系统。项目有确认门禁时先完成门禁；“只分析”不进入实施。

具体业务、品牌、第三方约束和已验证 workaround 属于目标项目，不随通用技能分发。优先使用已有记录，未经请求不创建 `.ai-dev` 或额外项目文档。

## 调用示例

Codex 使用 `$yuyin-dev`，Claude Code 使用 `/yuyin-dev`。

| 请求 | 预期行为 |
| --- | --- |
| 给 React 列表增加筛选，沿用现有组件库 | 读取状态和请求实现，选择适用 React 规则；验证成功、空结果与失败状态 |
| 排查 Spring 接口重复提交 | 复现、定位事务与幂等边界，保留 MyBatis/JPA 现状；补回归证据 |
| 分析 Node 服务超时，先不修改 | 只读确认调用链、超时与错误传播；给依据和最小验证方案 |
| 评估当前页面性能 | 先测量，再判断瓶颈；普通 React 不套 Next.js 专属 API |
| 审查当前 diff | 给具体位置、触发条件与影响；不为凑问题改代码 |
| 重构订单计算 | 先锁定公开契约，用特征测试证明去重后结果与副作用保持一致 |
| 升级一个已明确指定的依赖 | 查看目标迁移依据，限定依赖变化，分步验证并说明回退 |
| 只补旧代码测试 | 保持生产代码，使用独立期望覆盖边界并检查测试区分力 |
| 整理交接 | 在对话或用户指定载体保存事实、验证与下一步 |

## 选择专业技能

专业能力的选择、版本条件及降级方式统一维护在 [专业技能路由](../skills/development/shared/yuyin-dev/references/stack-skills.md)，此处不复制判断规则。各意图入口见 [yuyin-dev](../skills/development/shared/yuyin-dev/SKILL.md)。React 的状态、表单、请求及组件库实务由本地参考补充，性能、设计和测试技能按任务需要选择。

## 验收与反馈

实施前明确可观察结果，实施后检查实际行为、相关回归与 diff。性能结论有前后基线；UI 有实际页面或截图；仅编译成功不能证明业务成功。报告只列实际执行的验证及未覆盖范围。

已发布的内容快照保证文件可追溯，不保证所有模型、项目和工具环境都产生相同行为。试用重点记录误触发、强制改栈、越界修改、返工和验证质量；重复缺陷优先落实到项目测试或检查工具。

技能行为验收需使用带真实源码的小型任务，在 Claude Code 与 Codex 分别记录显式调用、自然语言选择及必要的专业技能直接调用。覆盖只分析、局部功能、Spring 数据访问、沿用已有浏览器工具、依赖缺失和小改动等场景；每例保存输入、预期与禁止行为、实际 diff、运行结果及未覆盖范围。文件校验、安装测试和静态审读不能替代这些行为记录，未执行的场景标记为待验证。

源码仓库提供 `npm run evals:check` 检查案例素材，`npm run evals:run -- --host codex --mode explicit --case node-readonly --out /tmp/yuyin-eval-new-run` 显式启动单次隔离验收；维护脚本不随技能包分发。模型修改的代码不由父验收器自动执行，人工源码审查后的动态检查另存证据。上游变化报告与行为矩阵只记录待验收范围，不能凭发布测试通过推定模型行为通过。

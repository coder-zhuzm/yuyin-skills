# 只补测试

先读已有测试命令、同类用例和被测公共契约，确定缺少的是逻辑、接口绑定、持久化还是用户交互证据。用户只要求补测试时，生产代码和业务行为保持原样；因可测试性确需调整生产结构时，先说明范围并按现有授权判断。

1. 按需求、调用方或独立样例确定预期。当前实现可帮助定位路径，不能用被测算法生成期望值。
2. 优先覆盖高价值分支：正常、边界、错误与副作用；使用项目已有 runner、fixture 和 Mock 边界。异步顺序用可控输入，避免靠随机等待制造通过。
3. 对已有正确行为，新增测试可以首次运行就通过；新增失败测试应能解释契约违背。发现生产缺陷时报告并保留复现，修复属于另一项行为变化。
4. 验证测试有区分力：通过独立反例或适当的受控变异，确认关键行为出错会失败。检查重复用例、只断言“调用过”和过度绑定私有结构的问题。
5. 运行新增及相关已有测试，检查隔离、清理与稳定性；数据库、浏览器等集成证据只由对应实际环境提供。

交付补充：新增覆盖的场景、原来遗漏的风险、测试命令和结果，以及发现但未修复的生产缺陷。覆盖率数字用于定位缺口，不代替行为判断。

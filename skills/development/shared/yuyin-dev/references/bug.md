# 故障诊断与修复

记录原现象、期望、最近变化、环境、已失败方案与有效 workaround。
区分用户已验证事实、当前代码证据和待验证假设，不重复忽略用户事实。

1. 复现：沿用真实环境和输入。不能稳定复现则先用现有观测缩小范围；新增日志、配置或复现文件须在实施授权内，不同时改多个变量。
2. 定位：区分 UI、后端、数据库、配置、容器、网络、上游和协议转换，追踪实际路径。
3. 缩小：最小输入/配置，一次验证一个假设。
4. 根因：解释为什么该输入在该位置导致该结果，不能只列可能性。
5. 修复：改产生问题的最小合理位置；要求持久修复时把有效临时方案转成稳定实现。
6. 防回归：核心逻辑补对应失败案例，验证修复前失败、修复后成功和邻近情况。

先相关测试，再按影响扩大；无新疑点不反复跑全部。
无关已有失败记录基线；真实上游不可达时验证本地构造/转换并标明联调未完成。
错误码需要结合实际响应、配置、调用层级与日志判断，不能替代根因证据。
复现或诊断可能写入文件、数据或外部系统时，先确认动作范围与授权；只读分析不自动实施修复。

完成输出：根因、修复、验证证据、未验证范围。
未确定时给最强证据和下一条能区分假设的检查，不让用户同时试十种方案。

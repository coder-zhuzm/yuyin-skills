# 新功能与行为修改

先在对话中明确轻量规格：触发条件、当前行为、期望、输入/输出、边界、验收场景与本次不做的事项；仅按用户要求落盘。
检查是否已有同类入口或扩展点，避免再造重复模块。
多个角色/渠道/租户/状态时列最小场景表，不能只验证成功路径。

1. 追踪受影响调用链、协议、数据和配置，说明兼容性与旧路径。
2. 分最小闭环；依赖任务顺序实施，不能无理由让多个 Agent 同时改同一文件。
3. 按风险决定验证方式：核心逻辑通过公共接口测可观察行为，有测试体系时先增加失败用例，再实现一个最小行为；界面细节用运行后的交互/截图。断言的预期值来自需求或独立样例，不能调用待测算法算答案，也不为便于测试暴露私有实现。
4. 小步保持可运行。新增依赖先确定当前栈是否已能解决。
5. 验证验收、失败路径和旧功能；跨层检查实际请求和返回，不能以编译通过代替业务通过。
6. 审查范围、权限、异常和额外配置。

存在外部副作用时补充重复提交、失败重试和并发场景；不存在这些能力时不添加无关架构。
使用临时素材或模拟服务时明确其验收边界，保留正式素材、真实依赖尚未验证的状态。

交付写一个具体前后变化、关键代码位置、实测结果和环境限制。
无明确授权则保留工作区，不自动推送或发布。

# 项目相关检查（按需）

## 企业微信 / RPA / Java

区分企微原生、中台 UI/权限、官方回调/会话存档与云手机 RPA。
检查消息去重、验签、成员/客户权限、租户、发送状态、重试、限流。
RPA 检查元素定位、等待、超时、幂等、前后台、步骤日志与人工接手。
Java 核对 Controller→DTO→Service→Adapter/Mapper→Entity/VO，
沿用已有 Spring/MyBatis，实际 Maven/Gradle 命令，不套 npm 示例。

## CPA / 模型网关 / Agent

区分客户端名、路由映射、上游名，检查协议、流式、工具调用、超时、账号。
用户已验证 workaround 纳入复现；不同来源的 429 不混同。
持久配置核对 provider 与处理阶段。一次比较一个账号/模型/参数/提示词因素。
工具有失败路径、循环/重试上限和副作用边界。

## 客服 / 知识库

同时支持中台产品与企微原生使用问题。重点登录、权限、消息、语音通话。
文档有负责人、版本、更新时间、权限和来源；先规范知识，不盲目扩向量库。
实际问题集验证检索、答案来源、未知/封控/账号异常转人工。
即时 IM 关注延迟与人工接手；知识检索与业务工具分别验收。
公司数据不混入通用更新包。

## 网站 / 视觉交互

保留目标：“残缺石像原位补全”不能改成石柱打开、马赛克或弹窗。
用户接受临时素材时先做 MVP，列清素材欠项与正式验收。
实际页面验证手机、点击、状态、加载失败、视觉对齐，构建不是视觉验收。
公开身份用“余音”，不加入真实个人信息；保留用户选定栈。

## Docker / 部署

核实 compose 服务名、卷、环境变量、镜像和 CPU 架构。
Mac arm64 与服务器 amd64 分清。清理/迁移核实锁、停服务、备份条件。
本地修改、构建、容器启动、生产行为分别报告，无实测标明阶段。

# 能否加入功能

默认只读，查现有实现、接口、状态、权限、数据和部署。

依次判断：
1. 是否已有：完整存在、部分存在、只有接口/UI/文档分别说明。
2. 是否必要：具体问题与更低成本替代。
3. 能否实现：官方 API、平台限制、内网依赖与权限；未知不写肯定。
4. 放在哪：现有扩展点还是独立模块，说明归属。
5. 影响：旧逻辑、调用方、数据/缓存、权限、性能、回滚。
6. 验证：哪个最小原型能回答关键假设，哪部分需要真实联调。

结论用“可以 / 满足条件后可以 / 暂不建议”。
先说明影响模块和验证量，有明确范围才估时间。
明显偏离原目标或有根本问题先提醒，不能迎合。
未获进一步实施授权，不改业务文件、不建 Issue、不发布。

输出：结论→代码/接口依据→最小方案→影响与条件→待验证项。

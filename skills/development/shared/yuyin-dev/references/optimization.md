# 判断与实施优化

先区分性能、可靠性、成本、维护性和体验。“复杂”不是性能瓶颈证据。
选择与目标相关的基线：延迟、请求或查询次数、错误率、资源消耗、重复分支或具体用户场景。没证据时提出低成本测量，不用大重构代替测量。

按收益、风险、实施与验证成本排列方案。可读性改进描述减少的概念与分支，不虚构提升百分比。“是否能优化”只评估；“优化一下”在明确目标与授权范围实施。

先锁定需保持的行为。旧代码无测试又需重构时补相关特征测试，不追求无关覆盖率。一次改变一个可归因因素，分离结构变化与新行为，同环境同输入比较前后。替换第三方服务或依赖时，同时比较质量、失败、兼容性与成本，不能仅凭价格切换生产配置。

日志摘要和工具输出压缩不能代替性能测量。保留诊断所需的原始错误、请求和协议差异；缺少证据不等于没有异常。新增测量工具或运行依赖须有本次任务依据与相应授权。

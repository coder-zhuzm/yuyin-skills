# 判断与实施优化

先区分性能、可靠性、成本、维护性和体验。“是否能优化”只评估；“优化一下”在明确目标与授权范围实施。

## 先列证据，再给结论

将现有依据分为两栏：
- **结构证据**：代码中能直接定位的调用关系、循环、查询次数、复杂度或维护成本，注明位置与适用输入。测试源码定义预期和模拟输入，仍属这一栏；它不是已执行的测试结果或测得的耗时。
- **测量证据**：实际运行或已提供的测量记录，注明环境、输入、方法、样本及结果，并区分本人运行与引用已有记录。

耗时量级、开销占比、主要瓶颈以及“是否存在性能瓶颈”只能由对应测量支持。没有测量时，这些项的结论为尚未确定；可以建议先测量、暂不改造，但不能把实现简短直接换算为开销低、可忽略或改造不会有收益。已提供的有效基准可以使用，结论范围限于该环境和输入。数值换算、配对差值和比值需可复核；缺少计算条件时保留原始记录和计算方法，不估算派生数字。

下一步选择能区分关键假设的最小测量：例如相同输入下对比调用路径，并分别观测依赖等待、运行时调度、超时与错误率。性能现状和改动收益分别验证，生产表现留待相应负载与真实依赖证据支持。

## 获准实施时

先锁定需保持的行为，按收益、风险、实施与验证成本选择最小方案。旧代码缺少测试又需重构时补特征测试，一次改变一个可归因因素，用同环境、同输入比较前后结果。

可读性改进描述减少的概念与分支；服务或依赖替换同时核对质量、失败、兼容性和成本。日志摘要、工具输出压缩与文件缩短不代替性能测量，保留诊断所需的原始错误和协议差异。

交付补充实际证据、仍待测的假设、方案取舍和下一条最小验证行动。

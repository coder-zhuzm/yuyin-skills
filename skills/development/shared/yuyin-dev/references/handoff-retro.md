# 交接与复盘

交接先在对话中汇总：原目标与边界、完成与未完成项、关键决定、改动文件、Git 状态、验证命令与结果、对应基线、阻塞和下一步。仅在用户明确要求保存文档时写入项目已有载体，不因多会话自动创建任务目录。

区分未提交、已提交、已推送、已部署。接手核对实际状态；代码或环境变化、验证记录不完整时再运行相关检查，避免重做已有且仍有效的结果。

复盘从证据找改进：文件定位困难可改善导航，机械错误可交给 lint 或测试，版本误判可补版本依据，诊断信息不足可改善脱敏观测。只给对当前问题有依据的建议，默认不直接实施。

项目事实留在项目；跨项目反复成立的方法才考虑进入通用技能。说明适用条件和最小验收，先获得用户对沉淀的确认，再维护技能，避免一次故障变成永久规则。

# 项目上下文

先只读，依次检查项目指令、源码入口、依赖与版本、构建/测试/启动配置、已有文档和有效运行记录。记录业务目的、目录职责、环境依赖、接口边界及可复用实现；未知项明确标注，不能用其他项目的经验补成事实。

优先复用项目已有记录格式。没有固定目录要求，不自动创建 `.ai-dev`、术语表、任务文档或 ADR。用户明确要求初始化或维护文档时，先检查已有载体，再在授权范围写入必要事实；普通“了解项目”只在对话中汇总。

项目约束、业务术语、临时任务状态与通用技能分别维护。业务术语按当前项目定义，命令来自配置或成功运行记录，重要取舍保留理由与适用条件。初次了解项目不升级依赖或改变业务架构。

交接时保留范围、下一步、Git 状态和验证基线。先利用可用的本地工具与资料，缺失工具时说明对本次任务的影响，不为建立上下文安装无关工具。

# 项目初始化与上下文

从真实仓库填写 .ai-dev/project.md；未知项标“待确认”，不编造。
记录业务目的、栈与版本、目录职责、构建/测试/启动命令、环境依赖、接口、边界和好的参考实现路径。
初次接入先读，不升级依赖，不改业务架构；只询问读不到的产品决策。

三类信息分别维护：
- 项目事实：.ai-dev/project.md，命令来自配置或成功运行记录。
- 业务词汇：.ai-dev/glossary.md，区分账户、客户、成员、渠道、会话等。术语表不存实现细节。
- 质量约束：.ai-dev/constraints.md，每条说明必须保持的行为、检查命令、执行阶段。

优先复用已有规范，不能再造冲突配置。只有真实取舍、难回退、未来难解释的决定写 ADR。
跨会话保存范围、下一步、git 状态与验证基线。缺少工具先尝试已有 CLI/本地方式，不加载无用 MCP。

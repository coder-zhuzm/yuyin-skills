# React 页面与业务实务

先查 React/框架版本、入口、已有组件库、路由、请求和表单工具，再沿一条“事件→状态/请求→渲染”链定位问题。小改动优先现有组件的扩展点。

| 当前问题 | 决策与可观察验证 |
| --- | --- |
| 状态归属与派生值 | 确定谁读写、是否跨组件共享以及是否可由已有输入计算；在最近的共同归属处维护一份事实来源，按当前复杂度选本地状态或现有 store。验证输入变化、重置和多入口更新 |
| 表单提交与校验 | 沿用表单库、字段约定与服务端契约；核对输入类型、错误显示、重复提交、失败后的输入保留和成功重置。检查键盘提交、标签和焦点反馈 |
| 请求与缓存 | 沿用项目请求库，确认缓存键包含影响结果的参数与权限范围；检查过期响应、取消、重试及组件卸载。验证旧请求后返回、失败、空数据和重新加载；按现有机制处理顺序，transition 不代替请求取消 |
| 组件库与交互 | 查现有受控/非受控 API、禁用、加载、错误和空状态。沿用主题与可访问组件，核对稳定 key、键盘操作及受影响屏幕尺寸 |
| 渲染性能 | 先观察具体请求瀑布或重渲染成本，再选相关单条性能规则；派生状态、memo 和组件拆分以实际问题为据。Next.js、服务端缓存及 React 19 专属能力按当前版本采用 |

纯计算可用单测；事件、表单和异步状态用现有组件测试；跨页面或视觉结果用运行页面和浏览器。静态源码检查不能证明布局、焦点或真实网络交互。

需要性能、组合、视觉设计或 UI 审查专项建议时，再按 [专业技能路由](stack-skills.md) 选择最少的专业规则。交付补充用户触发方式和前后可见行为。

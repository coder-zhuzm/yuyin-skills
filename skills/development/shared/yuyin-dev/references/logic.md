# 梳理已有逻辑

默认只读，不把建议写成当前行为。

1. 找实际入口：界面事件、HTTP 接口、回调、定时任务或 CLI。
2. 沿调用与数据流追踪到业务处理、外部依赖和返回结果，采用当前项目的层次与术语，不假设固定架构。
3. 标出与问题相关的选择条件、权限、状态、配置、重试和缓存。
4. 小链路用列表，复杂分支可用 Mermaid；证据定位到文件与符号。
5. 查异常产生、捕获、重试与用户可见结果。
6. 涉及数据写入时说明数据库、缓存、队列、第三方副作用和事务边界。

区分源码判断、实测、文档描述和推断。注释与实现冲突时指出；路由或分发决策应定位到实际代码，不能归因给未经证实的组件。
用户要优化建议才单独列出，不自动重构。

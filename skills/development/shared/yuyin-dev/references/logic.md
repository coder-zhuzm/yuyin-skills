# 梳理已有逻辑

默认只读，不把建议写成当前行为。

1. 找入口：按钮、Controller、回调、定时、CLI。
2. 追踪参数/DTO→Service/分发器→Adapter/Mapper→数据/VO。
3. 标出渠道选择、权限、租户、状态、配置、重试和缓存。
4. 小链路用列表，复杂分支用 Mermaid；证据定位到路径与符号。
5. 查异常产生、捕获、重试与用户可见结果。
6. 说明数据库、缓存、队列、第三方副作用和事务边界。

区分读代码、实测、文档描述和推断。注释与实现冲突时指出。
Java 渠道路由说清代码中谁选择 channel，不能说模型自动选择。
末尾给 1–3 个关键理解点；用户要优化建议才单独列，不自动重构。
